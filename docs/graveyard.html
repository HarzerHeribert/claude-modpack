How we know

What we tried and dropped

Eight mods ship. Far more ideas were built, measured and dropped. The reasons they failed taught us more than the features that worked, so here they are, grouped by what they taught.

Claude ignored it

A hint is easy to add and easy to ignore. Each of these spoke to Claude from the wrong place, and Claude carried on with what it was doing.

The grep hint

lsp-plus noticed a grep for a code symbol and attached a note: this LSP call lists exactly its uses. Correct, specific, one call away.

It fired 45 times across every benchmark run with the pack, and Claude acted on it 0 times0 of 450 of 45
45 notes
Opus 5.5, 13 Oct 2026. Following it meant two more steps for an answer Claude believed it already had.

Off by default. Replaced by the answer itself, attached to the grep; that mod, lsp-plus, left the pack in 0.7.0.

Four ways to make Opus delegate

A routing rule in the system prompt; the person's own "Delegate where you see fit"; the tool presented as an ability, implement_spec; telling Opus what each of its requests costs. Handing a feature to a cheaper model saves a third. If Opus did it by itself, everyone would save.

Opus 5.5, 13 Oct 2026 to carry, and none in 4 with the cost spelled out. Only an order works.

Dropped. delegate gives an order when you approve a plan; route gives one for feature and test prompts.

squeeze: the log squeezer

Replace a long test log with its failures, each with its file, line and message, and keep the full log on disk. Locally excellent: all 18 failures kept, nearly all of the rest of the log gone, in about a millisecond.

It cost more than it saved

A step saved by adding text is paid for again by every later step. Each of these saved something and still came out dearer.

a summary without a model

Compacting with a program: one cell that searches and sorts the conversation into a summary, or simply dropping the old tool calls and results. Output is the dearest token, and a program writes none of it.

It never left the noise

When the range of a measurement still includes no change at all, we cannot say a mod helps, so it does not ship. Most ideas end here.

Wrong about the important part

These worked on the easy part and failed on the part that mattered.

The projection that was wrong

An early analysis projected that hand-offs save more the fuller the session: about half of a feature’s cost at 200k tokens. Each step re-reads more in a full session, so removing steps should save more.

Measured in a 233k-token session, the feature saved 35%35% cheaper35% cheaper
No range in the source
2 per task and condition
Opus 5.5, 13 Oct 2026, about what it saved fresh, and a small question handed off cost up to 3.6 times as much. A session that knows the code needs far fewer steps.

Replaced by the measurement. Rule of thumb: hand off features and tests only.

Compression that forgets

A small, cheap model keeps only the passages of Claude's context that look relevant to a question. Every token in the context is paid for again on every step; the price of the small model is almost nothing.

4 of 5 answers right when each question had its own compression, 0 to 1 of 50 of 50 of 5
Five runs per case
Haiku 5.5 answering; ScaleDown Compress when one compression had to serve all five; one answer was confidently wrong. In a coding session the next question is never known in advance.

Not used.

Summaries of logs and worker reports

Let a small model summarize a test log or a worker's report before Claude reads it. Shorter text for every later step to re-read.

It named the failing tests but never kept a file and line; on an 18-failure log, four of five summaries were just the counts. A report that falsely said "the new tests pass" was repeated 3 of 3 times.

Not used. Extracting with a schema was right, but a local parser is as right in a millisecond.

a local route classifier

A classifier small enough to run on your own computer, in place of route’s outside service. No key, no service, and no prompt leaves the computer.

It got route’s clean test prompts right. On real prompts in the middle of a session most of what it handed off was not building work: 18%18%18%
101 hand-offs on the author's prompts
hashed n-gram logistic regression, 64 KB, 18 Oct 2026 of its hand-offs were right on the author’s own.

Not shipped. A prompt like “ok, build it like that” is feature work only with its conversation, which no classifier here sees.

It never reached the bench

One failed its own calibration; one was never measured at all. Neither ships.

Keyword pointers

BM25 keyword ranking over whole files, to point Claude at the right file before its first search. The strongest method in an independent evaluation of code-graph tools, with no index to keep fresh.

Calibrated on 13 prompts before a single benchmark run: it pointed "commit and push this" at an example program, then went quiet on 11 of 13 and was wrong on the other 2.

Dropped. Its deterministic half, where the name you typed is defined, became scout, measured below.

turn-savers

Lighter thinking on routine steps; the code at a failure attached to the failing run. Both sound like obvious savings.

Built, never measured.

Does not ship. A mod without a measurement is a guess with a version number.

What it taught us

  • The first good number is usually too good. Write down what would confirm it, then run it again.
  • A check that passes is not a check that checks. Agents’ own tests share their blind spots.
  • Models have habits. They grep, they tail logs, they keep work they can do. A feature that fights a habit loses; one that answers inside it wins.
  • Count what stays. A step saved by adding text is paid for again by every later step.
  • Removing is a result. Every idea here made the pack cheaper or simpler by staying out.
