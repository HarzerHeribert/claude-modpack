  1. lastenheft

    in the lab, offNo saving we could show−17 points

    The idea. A gate that turned an order into checkable requirements and would not let Claude stop until each was proven. Why it looked good: Agents that say "done" on half-finished work are a real problem; a gate against it looked like obvious value.

    What stopped it. A first batch looked promising (−17 points). The preregistered confirmation gave −4 points [−12.5, 0.0]: not confirmed. In 38 of 43 incomplete runs, every point on the list showed passed.

    Now. Kept in the lab, switched off. A checklist that turns green on incomplete work reassures falsely.

    • A requirements gate: 'said done while incomplete', first batchwith the gate vs without (paired)−17 points [−33, −4]
    • The same gate in a preregistered confirmation: not confirmedwith the gate vs without (paired)−4 points [−12.5, 0.0]

    “in 38 of 43 runs that were incomplete, every point on the list showed passed.” Lab notes 5

  5. The projection that was wrong

    correctedWrong about the important part−35%

    The idea. An early analysis projected that hand-offs save more the fuller the session: −53% for the feature at 200k tokens. Why it looked good: Each step re-reads more in a full session, so removing steps should save more.

    What stopped it. Measured in a 233k-token session: the feature saved 35% (37% before worker costs were corrected on 16 Oct), about what it saved fresh, and a small question handed off cost up to 3.6 times as much. A session that knows the code needs far fewer steps.

    Now. Replaced by the measurement. Rule of thumb: hand off features and tests only.

  7. Keyword pointers

    droppedFailed before a benchmarkno number

What it teaches

  • The first good number is usually too good. Write down what would confirm it, then run it again.
  • A check that passes is not a check that checks. Agents’ own tests share their blind spots.
  • Models have habits. They grep, they tail logs, they keep work they can do. A feature that fights a habit loses; one that answers inside it wins.
  • Count what stays. A step saved by adding text is paid for again by every later request.
  • Removing is a result. Every grave here made the pack cheaper or simpler.
