mods / delegate

delegate

A cheaper model builds what you approved.

costv0.4.3−22%a feature, handed off

The problem

Opus re-reads its whole conversation at every step, so building a feature step by step in a long session is expensive. A cheaper model could do the building, but Opus does not hand work off by itself: in the lab’s runs, never without an order.

What it changes

When you approve a plan of 20 lines or more, Claude hands the building to a Sonnet worker and checks the result. The worker ends its report in a fixed form that delegate checks itself, and the result starts with one line: Verified, or Not verified with each reason. On Verified, Claude reports without running anything again.

    What did not make it

    1. Four ways to make Opus delegate

      droppedClaude ignored it+18%

      The idea. A routing rule in the system prompt; the person's own "Delegate where you see fit"; the tool presented as an ability, implement_spec; telling Opus what each of its requests costs. Why it looked good: Handing a feature to a cheaper model saves a third. If Opus did it by itself, everyone would save.

      What stopped it. 0 hand-offs in 18 runs with the rule, 0 of 28 with the person's words, 0 of 8 as an ability (and the unused tool cost 11–18% to carry), 0 of 4 with the cost. Only an order works.

      Now. Dropped. delegate gives an order when you approve a plan; route gives one for feature and test prompts.

      “the tool presented as an ability, implement_spec(spec, check), with no word of delegation (0 of 8, and the unused tool cost 11–18% to carry)” Lab notes 5 · Lab notes 2

    2. Handing off the small stuff

      revertedCost more than it saved+150%

      The idea. Let delegate take read-only work too: lookups, traces. Why it looked good: If handing off a feature saves a quarter to a third, why not hand off lookups?

      What stopped it. Told to hand off a lookup, Opus turned it into an edit task, and the runs cost 17–40% more, leaving stray files in the repository (13–33% before worker costs were corrected on 16 Oct). A hand-off takes two to five requests of its own; a lookup takes one.

      Now. Reverted.

      • Handing off an explanation in a long sessiontold to hand off vs Opus alone with the pack; worker costs corrected 16 Oct+103%

      “the runs cost 17–40% more, leaving stray files in the repository” Lab notes 5

    3. The projection that was wrong

      correctedWrong about the important part−35%

      The idea. An early analysis projected that hand-offs save more the fuller the session: −53% for the feature at 200k tokens. Why it looked good: Each step re-reads more in a full session, so removing steps should save more.

      What stopped it. Measured in a 233k-token session: the feature saved 35% (37% before worker costs were corrected on 16 Oct), about what it saved fresh, and a small question handed off cost up to 3.6 times as much. A session that knows the code needs far fewer steps.

      Now. Replaced by the measurement. Rule of thumb: hand off features and tests only.
