lsp-plus

A search for a name answered by the language server.

code intelligencev0.4.1−25%requests on a rename

The problem

To find who calls a function, Claude searches the text with grep. Grep returns every line with the name in it: imports, calls, the definition, comments, a namesake. It does not say which function each call sits in, so Claude often reads further.

What it changes

When Claude’s search looks for a code name, lsp-plus asks the language server, the engine your editor uses, and attaches its exact answer to the search result: each caller named by its function, or the references by file. Claude needs no extra step. Where no search asks for a name, it says nothing.

What did not make it
  1. 
  
    The grep hint
    off by defaultClaude ignored it0 of 45
    
  
    
    
    The idea. lsp-plus noticed a grep for a code symbol and attached a note: this LSP call lists exactly its uses. Why it looked good: Correct, specific, one call away.
    
    
    What stopped it. Fired 45 times in every benchmark run with the pack; Claude acted on it 0 times. Following it meant two more requests for an answer Claude believed it already had.
    
    
    Now. Off by default. Replaced by the answer itself, attached to the grep.
