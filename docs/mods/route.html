Mods

route

Feature and test work goes to the cheaper model by itself.

It comes with the pack and stays off until you turn it on.

The moment

You type: implement pagination for the users endpoint.

Without route

Claude reads the code and builds the feature itself, step by step. A hand-off would have been cheaper, but only you can ask for one, and you would have to remember every time.

With route

route asks a small, fast classifier what kind of work each prompt is. Only feature or test work gets the order, in your name, to hand it to delegate’s worker before reading the code. A question, a rename or a typo fix stays with Claude, as before.

Pick a prompt and see what route does with it. The labels and scores are the ones the classifier gave in our test.

Where it doesn’t help

It is off until you turn it on, because the start of each prompt goes to an outside classifier in the US. Prompts under 40 characters are never sent, so a short “write tests for the parser” stays with Claude. And every prompt in our tests was a complete specification; on a vague request, a task written before reading the code may be a worse task. We haven’t tested that.

Turn it on or off

Turn it on with /mods route on and a key for TypeSafe’s Jev or ScaleDown. It needs delegate. Every option is in the README; the code is in route/.
